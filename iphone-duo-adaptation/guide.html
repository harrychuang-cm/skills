cm-skills · iphone-duo-adaptation

一套流程，
讓每個 App 都摺得好。

從盤點、設計決策、實作到自動化截圖驗證。Lego 與非 Lego 的 iOS App 都能用。

流程

五個階段，每一步都有產出。

先讓畫面開合後會重新排版，再談版面。每個決定都記下來、拍成截圖給設計師看。

  1. 盤點

    掃出寫死螢幕尺寸的程式碼，修掉或列例外。

    工程docs/duo/inventory.md
  2. 問卷

    設計師回答 10 題，決定這個 App 的版面。

    設計師docs/duo/decisions.md
  3. 實作

    依答案開開關或照 UIKit 做；只在大螢幕生效。

    工程程式碼＋測試
  4. QC

    模擬器自動摺疊、展開，逐頁截圖並套規則判定。

    工程跑、設計師看shots/、report.html
  5. 審閱

    每項修改的前後對照與待決清單，進下一輪。

    設計師Before／After

問卷

設計師只要回答 10 題。

每題的預設都是照系統。只有截圖看得出問題，才往下改。

  1. Q1系統直欄用
  2. Q2按鈕怎麼進直欄有直欄就進
  3. Q3直欄上下怎麼分系統預設
  4. Q4按鈕要不要各自一顆系統預設
  5. Q5標題列留什麼系統預設
  6. Q6直欄與視窗底色系統預設
  7. Q7哪些頁改清單＋內容兩欄全部單欄
  8. Q8底線頁籤在橫向維持橫排
  9. Q9開放哪些方向直向＋landscapeLeft
  10. Q10Tab 列系統 Tab

為什麼用問卷，不給標準答案

2026 年 10 月有四個 App 各自做了 Duo 適配，選擇都不一樣。

App按鈕兩欄頁籤
莎拉全進直欄，上導覽下動作更多頁、語音回放改左側
不魯展開留上方，合起進直欄單欄維持
老簡標準按鈕，照系統單欄維持
當沖標準按鈕＋溢位順序單欄維持

答案寫進 templates/duo-decisions.md，沒決定的題目一律用預設，不猜。

規則

33 條規則，四個核心。

每條規則寫成條件 → 做法 → 為什麼，附實測數值，並對應問卷題號。

上導覽，下動作

返回在直欄頂端，分享、收藏在底部，標題列只留標題。

L1–L15・Q2–Q5

橫向頁籤靠左

變寬時底線頁籤改左側直排，從導覽列下方開始。

L16–L19・Q8

大螢幕分兩欄

清單與內容並排；轉直向或摺起就收回單欄。

L20–L25・Q7

開合不搬家

選取狀態不變、內容只建一份；一般 iPhone 一行都不變。

L26–L33・必做

系統做不到的事，先知道再設計

  • 有 Tab 的頁面：直欄底部留給 Tab 圖示，動作鈕排不到底部。
  • 寬按鈕：超過 84 pt 的自訂按鈕進直欄會變成一塊白色。
  • 巢狀導覽控制器：直欄只顯示一條導覽列的按鈕，外層的會消失。
  • 直欄的左右：由硬體決定；只開 landscapeLeft 才固定在右側。

實作

兩條軌道，同一套規則。

所有改動都放在預設關閉、只在大螢幕（短邊 > 440 pt）生效的開關後面。

Lego 生產線 App

打開共用層的開關。

直欄按鈕、左側欄、兩欄、影音內頁都已做進共用框架；App 依問卷答案設定，主 Tab 建立前完成。

// didFinishLaunching，主 Tab 建立前
let isLarge = { isCurrentSceneLargeScreen() }
LegoVerticalBar.isEnabled = true
LegoVerticalBar.placesAllItemsInColumn = true
LegoSegmentSideMenu.isEnabledProvider = isLarge
LegoMoreSplitLayout.isEnabledProvider = isLarge
references/track-lego.md
非 Lego App（UIKit／SwiftUI）

用系統 API 照做。

每條規則都對到 UIKit 的做法，附不魯、老簡、當沖三個 App 踩過的坑。

#if compiler(>=6.4)  // iOS 27.1+
item.axisBehavior = .verticalPreferred
item.sharesBackground = false
// 已顯示的按鈕要先清空再指定才會移動
navigationItem.rightBarButtonItems = nil
navigationItem.rightBarButtonItems = items

自動化 QC

模擬器自己摺，自己拍。

工具與 App 無關；分頁名稱、彈窗、要走哪些頁，全部寫在一份 JSON。

  1. 摺疊／展開duo_hinge
  2. 依計畫走訪walk-plan.json
  3. 截圖＋階層shots/、xchg/
  4. 規則判定analyze.py
  5. 報告report.py

走訪計畫長這樣

{
  "app": { "readyElement": {"button": "首頁"},
           "launchDismiss": [{"label": "我明白了"}] },
  "scenarios": [{
    "id": "A", "mode": "matrix",
    "postures": ["folded", "unfolded",
                 "unfolded-portrait", "refolded"],
    "screens": [
      {"id": "01-首頁", "steps": [{"tab": "首頁"}]},
      {"id": "02-內頁", "steps": [{"tab": "首頁"},
                                 {"firstCell": true}],
       "leaveAfter": true }]
  }]
}

導航都在摺疊時做（展開時的點擊會落到外螢幕），之後只切姿態、不碰畫面。

會自動抓到

  • 嚴重content-missing

    開合後內容整個不在畫面上。

  • 嚴重window-size

    視窗沒跟著螢幕變，畫面不會重排。

  • 高cached-screen-size

    元件寬高等於另一塊螢幕：啟動時快取的尺寸。

  • 高restore-mismatch

    摺回後位置與原本不同。

規則判定只是候選；每張截圖都要人看過。

開始

說一句話就能開始。

把 App 路徑和設計師的名字告訴 agent，說清楚這次做到哪個階段。

用 $iphone-duo-adaptation 幫 <App 路徑> 做 iPhone Duo 適配，設計師是 <名字>，這次先做盤點和問卷。
用 $iphone-duo-adaptation 對 <App 路徑> 跑 Duo QC 情境 A 和 L，報告放 <目錄>。
用 $iphone-duo-adaptation：依 docs/duo/decisions.md 的答案改 <頁面>，做完補 Before／After。
環境

Xcode 27.1、iOS 27.1 iPhone Duo 模擬器、Python 3＋numpy。

設計師

回答問卷、審閱每輪的前後對照、決定待決事項。

找不到 skill 時

請 agent 先讀 iphone-duo-adaptation/SKILL.md 再照流程做。
