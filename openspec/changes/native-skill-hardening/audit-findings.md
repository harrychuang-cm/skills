### [major] confirmed — FPI 的 `## Prototype Parity Sweep` 是獨立章節（13 行、含機制與誠實條款），NPI 把它壓縮成 UI Verification 結尾的兩句。遺失了三樣東西：`prototypeRoute=<route-id>` 這個隔離渲染機制、Scope `C` 的排除、以及「跑不起來就要明說哪些 B 面沒驗，不得回報 parity 通過」。
**證據**：FPI references/verification-reporting.md:46-58 全章。其中第 48 行界定範圍：「Parity covers every surface the Prototype To Frontend Map marks Scope `B`, not only newly created components … checking components in isolation leaves the assembled screen unverified.」第 52 行給機制：「compare the production surface side by side with the prototype's corresponding route (`prototypeRoute=<route-id>` renders it in isolation)」。第 56 行排除 A 與 C。第 58 行是誠實條款：「When the prototype Storybook cannot be run, say so and record which `B` surfaces went unverified rather than reporting parity as passed.」NPI references/verification-reporting.md:45 全部只有：「For prototype parity on Scope `B` surfaces, run a side-by-side comparison against the prototype Storybook route when it can be run; `ui-compare-to-reference` or `ui-pixel-align-report` can own that check … Scope `A` surfaces are excluded…」——「when it can be run」是條沒有下文的免責條款。

### [blocker] overstated — 導航對映表多數格子不是可執行 API，`popToRoot` 的 `popUpTo` 用法無法編譯
**證據**：`references/implementation-workflow.md:89-102`。`modal | Blocking modal presentation | Dialog destination or blocking modal route`（iOS 側非 API，SwiftUI 沒有 modal primitive）；`sheet | .sheet | Bottom sheet (Material) or dialog destination`（dialog 不是 sheet，手勢／insets／無障礙焦點全不同）；`fullscreen | .fullScreenCover | Full-screen dialog destination`（Compose 全螢幕通常就是一般 `composable` destination）；`replace | Replace the path root | navigate with popUpTo(...) { inclusive = true }`（「Replace the path root」歧義；Compose 側沒說 popUpTo 誰）；`popToRoot | Clear the navigation path to the flow root | popUpTo(startDestination)` —— `popUpTo` 是 `NavOptionsBuilder` 的 DSL 函式，只能寫在 `navigate(route) { ... }` 或 `navOptions { }` 內，不能單獨呼叫來回退，純回退要用 `navController.popBackStack(route, inclusive = false)`。`none` 兩側都只有敘述沒有 API。

**修法**：把兩張表改成具體 API 並新增「Requires（最低版本／依賴）」欄：push → `NavigationStack(path:)` + `.navigationDestination(for:)`（iOS 16+）／`composable<Route>` + `navController.navigate(Route(...))`；modal → `.sheet {...}.interactiveDismissDisabled(true)` 或 `.fullScreenCover`／`dialog<Route>` + `DialogProperties(dismissOnBackPress = false, dismissOnClickOutside = false)`；sheet → `.sheet` + `.presentationDetents`／Material3 `ModalBottomSheet`（或 `navigation-material3` 的 `bottomSheet` destination），明文禁止以 dialog 代替；fullscreen → `.fullScreenCover`／一般 `composable` destination（若必須用 dialog，註明 `usePlatformDefaultWidth = false`）；replace → `path = [newRoute]` 或更換 root view／`navigate(new) { popUpTo(current) { inclusive = true } }`；popToRoot → `path.removeAll()`／`navController.popBackStack(startRoute, inclusive = false)`；none → `.navigationBarBackButtonHidden(true)` + `.interactiveDismissDisabled(true)`（並註明 SwiftUI 的 interactive pop gesture 跟隨 back button 一起消失）／見預測性返回那一條。
**查核註記**：該表標題就是「Navigation Semantics Mapping」，多數格子刻意停在語意層：modal 在 SwiftUI 本來就沒有單一 primitive（正解視情況是 fullScreenCover 或 sheet + interactiveDismissDisabled），`none` 寫「Intercept back」正是 BackHandler 的定義，replace 的 Compose 側 `navigate with popUpTo(...) { inclusive = true }` 也是標準寫法。真正錯的只有一格：popToRoot 的 `popUpTo(startDestination)`——popUpTo 確為 NavOptionsBuilder DSL，純回退應為 navController.popBackStack(startDestination, false)。但同表上一列（:99）就給了 navController.popBackStack()，且此錯誤在 :18 的 assembleDebug 立即編譯失敗被抓到。單格事實錯誤成立，「多數格子不可執行」與 blocker 等級不成立。
