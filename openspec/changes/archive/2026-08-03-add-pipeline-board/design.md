## Context

`cm-skills` 收錄多個設計到工程的 skill，彼此之間有真實的先後依賴。這些依賴不是文件上的說法，而是執行期強制的：`design-system-to-storybook` 的來源追蹤腳本在找不到設計系統套件的證據檔時直接中止並指名缺少哪個檔案。

`agent-automation-orchestrate` 每次執行都寫下持久摘要，內含階段、選用的 runner、fallback 過程、逐項驗證結果與必要產物檢查。`status.mjs` 已匯出查詢函式且自帶路徑包含性檢查。

設計系統審閱工具已經解析「開發者決定」欄位、把空白與待確認類字樣視為未解決、把該列標記為需審閱，並彙總出待決總數。但五支 extractor 腳本目前都沒有機器可讀輸出，該統計只出現在人類閱讀的 HTML 中。

本專案已三次使用「零依賴腳本產生自足 HTML」的慣例，這是既有且可信賴的作法。頂層 skill 由既有安裝器自動探索，安裝器要求 SKILL.md 的名稱與資料夾同名。

使用者為設計師，且明確要求本工具不得是 Figma plugin，因為並非每個專案都使用 Figma。

## Goals / Non-Goals

**Goals:**

- 讓設計師在不安裝任何東西的情況下看懂一條自動化流程會做什麼、跑到哪、何時輪到自己。
- 讓每一條連線的狀態都能追溯到下游工具實際會中止的條件，使圖不可能與工具行為矛盾。
- 讓來源不限於 Figma，依專案實際證據決定顯示哪些來源。
- 讓流程板在從未安裝過任何自動化元件的專案上也能產生有意義的輸出。

**Non-Goals:**

- 不提供拉線編排、圖執行引擎、執行按鈕或排程觸發。
- 不提供即時串流進度。
- 不修改 `agent-automation-orchestrate` 的任何語意，只讀取其產出。
- 不依賴或修改 Design Automation Hub、Figma plugin 或任何連接埠服務。
- 不新增串鏈編排與鏈序執行器。

## Decisions

### 流程板是獨立頂層 skill 而非受管模板的一部分

`pipeline-board` 以頂層 skill 形式存在，由既有安裝器自動探索並鏡射到三個 agent 表面。它不進入任何受管模板，因此沒有 manifest、沒有雜湊收據、沒有受管檔案覆寫路徑，也沒有人工匯入步驟。

替代方案是放進既有受管模板。該路徑要求版本耦合的人工驗收與收據雜湊比對，在資料模型尚未穩定的階段會讓每次迭代都付出不成比例的代價，因此拒絕。

### 流程定義是側車檔，不進入專案任務契約

流程的順序、階段標題與交接關係存放在專案內的獨立定義檔。專案任務契約的欄位集合是封閉的且明文拒絕未知欄位，加入依賴關係欄位會使既有設定失效。定義檔不被任何執行器讀取，刪除它不影響任何自動化執行。

### 連線狀態必須引用下游工具實際中止的條件

定義檔中每一條交接關係都必須記載它所鏡射的下游中止條件，包含負責中止的腳本與該腳本要求的檔案。檢查器驗證被引用的腳本存在且確實檢查該檔案。

替代方案是只宣告路徑而不引用強制點。那樣的宣告會隨下游腳本演進而腐化，且無法察覺；本專案已存在一個腳本讀取的狀態檔沒有任何產生者的實例，證明這種腐化會真實發生。

### 來源節點依專案證據決定且支援多種來源

流程的起點不寫死為 Figma。定義檔宣告一組候選來源，每個來源附帶判定其存在的證據條件。流程板只顯示證據成立的來源；全部不成立時顯示尚未提供來源，並列出可接受的來源種類。

### 節點狀態區分檔案已產出與已驗證

節點狀態的命名嚴格區分兩件事：產物檔案存在，與稽核指令實際以零退出通過。前者不得顯示為已驗證。缺少稽核結果時顯示為未驗證而非通過。

### 連線的第三種狀態是已過期

除了成立與未成立，連線另有已過期狀態：上游產物的修改時間晚於下游步驟最近一次成功完成的時間。這不需要任何新的量測，且填補了純存在性判定的假綠燈缺口。

### 執行進度是推導的，逾期顯示需確認而非假進度

流程板讀取既有的持久摘要取得階段、選用 runner、fallback 與驗證結果。持久紀錄在 agent 執行期間完全靜止，因此不呈現任何動態進度指示。當紀錄停留在執行中且距最後更新超過該任務設定的逾時上限加上寬限時間時，顯示為可能已停止並提示人工確認。

未執行的驗證項數量由設定的項數減去摘要中已記錄的項數推導，因為摘要在第一項失敗時即停止記錄，直接顯示已記錄項數會把三項中通過一項誤報為全部通過。

### 待決事項數量來自既有審閱統計的機器可讀輸出

設計系統審閱工具新增機器可讀輸出模式，輸出既有的各類統計與需審閱列。流程板消費該輸出顯示待決數量。此模式不改變既有 HTML 輸出行為。

替代方案是由流程板自行重新解析審閱來源。那會複製既有的解析規則並造成兩份判定標準，因此拒絕。

### 檢查器以確定性暫存專案驗證，不呼叫付費執行器

檢查器建立暫存專案裝置，涵蓋空專案、僅有來源、部分完成、全部完成、上游較新造成過期，以及被引用的下游中止點失效等情境，全部以檔案系統操作與既有腳本完成，不呼叫任何 AI 執行器或網路。

## Implementation Contract

### 行為

在任一專案根目錄執行建置與渲染兩支指令後，產生單一 HTML 檔。以瀏覽器開啟該檔可看到一條由節點與連線組成的流程，每個節點顯示其狀態、已產出與缺少的檔案、待決事項數量，每條連線顯示成立、未成立或已過期及其原因。

在從未安裝任何自動化元件的專案上，指令仍以零退出完成，流程板顯示所有節點為尚未開始且執行區塊為無資料。

### 介面與資料形狀

流程定義檔為 schema 版本 1，包含來源候選清單與階段清單。每個來源候選包含識別碼、設計師可讀名稱與判定其存在的證據路徑。每個階段包含識別碼、設計師可讀標題、消費路徑、產出路徑、稽核指令、待決統計來源，以及每條交接關係所鏡射的下游中止條件。

建置指令輸出衍生狀態物件，包含 schema 版本、專案根目錄、來源清單、每個階段的狀態與證據、每條連線的狀態與原因，以及執行區塊。執行區塊為無資料或包含階段、選用 runner 識別碼與標籤、fallback 過程、驗證通過失敗未執行的計數與產物存在情形。

渲染指令消費該狀態物件輸出 HTML。輸出不得包含存取碼、憑證、展開的執行參數、原始提示或環境值。

`generate_review_html.mjs` 新增機器可讀輸出模式，輸出既有統計欄位與需審閱列，且不改變既有 HTML 輸出。

### 失敗模式

定義檔缺失、schema 版本不符、路徑逸出專案根目錄、交接關係引用不存在的下游腳本，或引用的腳本並未檢查所宣告的檔案時，建置指令以非零退出並輸出穩定錯誤碼，且不產生任何輸出檔。

執行摘要不存在或無法解析時，執行區塊為無資料，其餘流程板內容照常產生，指令仍以零退出。

### 驗收標準

- `node pipeline-board/scripts/check-pipeline-board.mjs` 以零退出，輸出的檢查名稱包含空專案、僅有來源、部分完成、全部完成、上游較新造成過期、失效的中止點引用，以及執行區塊逾期六種情境。
- 在一個沒有任何自動化設定的暫存專案上，建置與渲染皆以零退出並產生可開啟的 HTML。
- 產生的 HTML 不含任何外部資源參照，可在無網路環境開啟。
- `node design-system-extractor/scripts/generate_review_html.mjs` 的既有 HTML 輸出在新增機器可讀模式後逐位元組不變。
- `node scripts/install_agent_skills.mjs --dry-run` 將 `pipeline-board` 列為可安裝 skill。
- `git diff --check`、`spectra analyze add-pipeline-board --json` 與 `spectra validate add-pipeline-board` 全部通過。

### 範圍邊界

**在範圍內**：`pipeline-board` skill 及其定義參考、預設定義檔、建置腳本、渲染腳本、檢查器、`generate_review_html.mjs` 的機器可讀輸出模式，以及 README 的入口連結。

**在範圍外**：串鏈編排、範本層步驟欄位、鏈序執行器、執行按鈕、排程觸發、即時串流、Design Automation Hub 的 Coordinator 與 Plugin、`agent-automation-orchestrate` 的任何語意變更、其餘四支 extractor 腳本的輸出模式。

## Risks / Trade-offs

- [宣告的路徑與下游實際中止條件隨時間脫節] → 每條交接關係必須引用強制點，檢查器驗證該腳本存在且確實檢查該檔案。
- [純存在性判定會把過期的產物顯示為成立] → 引入已過期狀態，以修改時間與完成時間比較判定。
- [設計師誤以為流程板可以啟動執行] → 流程板無任何執行入口，並在頁面明確說明啟動方式與由誰執行。
- [執行紀錄在 agent 執行期間靜止，可能被誤讀為當機] → 逾期時顯示可能已停止並提示人工確認，不顯示動態進度。
- [待決統計依賴新的機器可讀輸出] → 該輸出以既有統計為來源，且要求既有 HTML 輸出逐位元組不變。
- [流程板在沒有任何自動化的專案上可能毫無內容] → 明確顯示尚未開始與可接受的來源種類，使其在零狀態下仍具說明價值。

## Migration Plan

1. 建立 skill 外殼、定義參考與預設定義檔，確認安裝器能探索到。
2. 實作建置腳本的推導邏輯與錯誤碼，先以暫存專案裝置驗證。
3. 為設計系統審閱工具新增機器可讀輸出模式，確認既有 HTML 輸出不變。
4. 實作渲染腳本與檢查器，補齊六種情境。
5. 在 README 加入入口連結。

回滾方式為移除 `pipeline-board` 目錄並還原審閱工具的輸出模式。流程板不寫入任何專案狀態、不修改既有設定、不建立服務，因此回滾不需資料遷移。
