# 修改與驗證記錄

本次修改 skill 指令、Codex 顯示資訊與 README 的對應小節，並更新 executive-presentation-skill 規格。以下驗證記錄以實作階段為準，當時尚未更新使用者安裝副本、生成實際簡報或提交推送；後續安裝另記於文末。

## 情境審閱

下表是逐項閱讀修改後指令的結果，用來確認規則完整且互相一致；不是各 agent 實際生成簡報的行為測試。

| 情境 | 審閱結果 |
| --- | --- |
| 新手引導會議記錄 | 四頁模板先說建議，再說問題、方案案例及驗證；標題改為具體重點，框架縮寫留在內部整理方法。 |
| 只有找回收藏項目的質性改善 | 要求說明誰能更容易完成什麼及觀察方式，不強迫營收或 ROI。 |
| 人力成本、營運成本與交付速度 | 明示合併重疊效益，使用不同理由，不為填模板強湊第三項。 |
| 年效益 1,200,000、年成本 800,000 | 同期間淨效益公式得到 50%；仍保留零成本、淨效益重扣及效益成本比區別。 |
| 只有 AI 客服試點主題 | 允許先做草稿並主動補證據；當地成效及缺少的數據維持預期／待驗證，不捏造案例。 |
| 空輸入或未填模板 | 先問主題，不自行選題搜尋。 |
| 沒有負責人、日期、目標值 | 提議安排標為待確認，相對時間有基準；至少一項行動驗證改善，不只交設計稿。 |
| 提到尚未讀取的研究文件 | 優先查可用文件工具，讀取原文後才引用；無權限或找不到時明示。 |
| 指定只用提供資料 | 停止外查，保留證據缺口並使用現有內容。 |
| 缺搜尋工具或聚焦搜尋無成果 | 一次聚焦查詢及一次針對性調整仍無資料即交代限制，完成有條件草稿，不宣稱已查證。 |
| 只有兩步註冊畫面、沒有成效數據 | 明示做法參考，不由截圖推導轉換提升；不重複索取已有截圖。 |
| 有案例文字但缺畫面 | 用用途明確的一句話詢問截圖或連結，繼續不依賴素材的工作，標記未取得的畫面。 |
| 使用者拒絕補件 | 不反覆追問，沿用可用來源；概念示意不冒充真實產品畫面。 |
| 三種 agent 的發現與安裝 | 維持 skill 名稱與安裝器介面；dry-run 正確解析三個目的地。 |
| 無 PowerPoint 產檔能力 | 交付文案並說明未產檔，不把 Markdown 草稿稱為已完成簡報檔案。 |
