## Context

pipeline-board 已為單一專案提供由磁碟證據推導的流程板:建置腳本 `pipeline-board/scripts/build-pipeline-status.mjs` 在專案根目錄產出 schema 版本化的狀態物件(來源清單、各階段狀態與證據、各連線成立/未成立/已過期及原因、待決事項數、執行區塊含可能已停止標記),渲染腳本消費該物件輸出單一自足 HTML。該變更(add-pipeline-board)的資料層已完成,渲染層在本變更開始前會先完成。

設計師同時照看多個專案,需要一張跨專案總覽:每個專案跑到哪、卡在哪、有多少待決事項。本專案已四度採用「零依賴腳本產生自足 HTML」慣例;頂層 skill 由既有安裝器自動探索,SKILL.md 名稱須與資料夾同名。

## Goals / Non-Goals

**Goals:**

- 讓設計師開啟一個 HTML 檔就能看到所有受追蹤專案的自動化狀態:目前階段、卡住原因、待決事項數、執行狀態。
- 每張專案卡片可連到該專案自己的流程板,且連結永不失效——總覽與各專案板由同一次聚合產生。
- 個別專案的錯誤(路徑不存在、定義檔無效)以錯誤卡片呈現,不中斷其他專案的聚合。
- 儀表板明示自己是靜態快照:頁面標示產生時間與更新方式。

**Non-Goals:**

- 不做即時串流、自動輪詢或常駐服務;更新即重跑指令。
- 不提供任何啟動執行的按鈕、排程觸發或編排能力。
- 不修改 pipeline-board 與 agent-automation-orchestrate 的任何語意,只以子行程呼叫其既有指令並消費輸出。
- 不做跨機器收集;所有專案根目錄都在本機檔案系統。
- 不做歷史趨勢或時間序列儲存;只有當下快照。
- 不聚合 pipeline-board 以外的資料來源、不依賴 Figma。

## Decisions

### 儀表板是獨立頂層 skill 而非併入 pipeline-board

`portfolio-dashboard` 以頂層 skill 形式存在,由既有安裝器自動探索。替代方案是把聚合腳本加進 pipeline-board;該路徑會重開一個已完成變更的範圍,並把「專案內側車檔」與「跨專案組合設定檔」兩種受眾與生命週期不同的定義混進同一個 skill,因此拒絕。

### 組合定義檔是使用者維護的獨立設定檔

組合定義檔為 schema 版本 1 的 JSON,列出受追蹤專案:每項含識別碼、設計師可讀名稱、專案根目錄路徑。路徑可為絕對路徑或相對於定義檔所在目錄。skill 附帶範例檔 `portfolio-dashboard/assets/default-portfolio.json`,格式說明在 `portfolio-dashboard/references/portfolio-definition.md`。定義檔由使用者放在任意位置,建置指令以參數指定其路徑;它不進入任何專案的任務契約,刪除它不影響任何自動化執行。

### 聚合以子行程呼叫既有指令而非重新實作推導

聚合腳本對清單中每個專案,以子行程呼叫 pipeline-board 的建置指令取得該專案的狀態物件,再呼叫其渲染指令產出該專案的流程板 HTML。pipeline-board 腳本位置以聚合腳本自身位置解析(同一 repo 內的兄弟 skill)。替代方案是匯入其內部函式或重新實作推導;那會產生兩份判定標準並耦合內部 API,狀態物件才是穩定契約,因此拒絕。

### 同一次聚合產生總覽與全部專案板，輸出集中於單一目錄

一次建置對每個成功的專案同時產出狀態物件與該專案的流程板 HTML,渲染步驟再產出總覽 HTML。全部輸出寫入單一輸出目錄:總覽檔加上以專案識別碼命名的各專案板。卡片連結為目錄內相對路徑,整個資料夾可攜、可分享,且總覽與各板必然來自同一時刻的快照。輸出目錄預設為組合定義檔所在目錄下的 dashboard 子目錄,可用參數覆寫。portfolio 指令本身不寫入任何受追蹤專案的目錄;一次聚合中唯一發生在專案內的寫入,是 pipeline-board 建置指令刷新該專案自己的 `.pipeline-board/status.json`——那是該指令自身的文件化行為(其輸出路徑被強制限制在專案根目錄內),不是 portfolio 指令的寫入。

### 個別專案失敗以錯誤卡片呈現，不中斷整體

專案根目錄不存在、其流程定義檔無效、建置子行程非零退出、或其狀態物件 schema 版本不符時,該專案在總覽上顯示為錯誤卡片並附穩定錯誤碼與原因,聚合繼續處理其餘專案,整體指令仍以零退出。只有組合定義檔本身無效(缺失、schema 版本不符、專案清單為空、識別碼重複、路徑逸出檢查失敗)時,建置指令才以非零退出並輸出穩定錯誤碼,且不產生任何輸出檔。

### 卡片的卡住原因依固定優先序推導

每張卡片的注意事項依以下優先序決定,取第一個成立者:(1) 執行區塊標記可能已停止 → 顯示需人工確認;(2) 依定義檔階段順序第一條未成立或已過期的連線 → 顯示該連線與其原因;(3) 待決事項數大於零 → 顯示待決數量;(4) 以上皆無 → 顯示流程健康,並區分全部已驗證與僅檔案已產出。此優先序寫死於聚合輸出,渲染層不得自行重排。

### 建置與渲染拆為兩支指令

沿用 pipeline-board 的建置/渲染分離:`portfolio-dashboard/scripts/build-portfolio-status.mjs` 產出組合狀態物件(JSON),`portfolio-dashboard/scripts/render-portfolio-dashboard.mjs` 消費它輸出總覽 HTML。組合狀態物件本身即為可供未來工具消費的聚合契約。

### 檢查器以確定性暫存裝置驗證，不呼叫付費執行器

`portfolio-dashboard/scripts/check-portfolio-dashboard.mjs` 建立暫存組合與暫存專案裝置,涵蓋:健康專案、含未成立連線的專案、含已過期連線的專案、執行逾期專案、專案根目錄不存在、組合定義檔無效(含空清單與識別碼重複)、狀態物件 schema 版本不符。全部以檔案系統操作與既有腳本完成,不呼叫任何 AI 執行器或網路。

## Implementation Contract

### 行為

使用者維護一份組合定義檔後,依序執行建置與渲染兩支指令,在輸出目錄得到一個總覽 HTML 與每個專案各自的流程板 HTML。以瀏覽器開啟總覽,每個專案一張卡片,顯示名稱、目前所在階段、依固定優先序推導的注意事項(需人工確認/卡住的連線與原因/待決數/健康)、執行區塊摘要,以及指向該專案流程板的相對連結。頁面標示產生時間與重新產生的指令名稱。

錯誤卡片顯示專案名稱、錯誤碼與原因,不含連結或含指向不存在檔案的連結(必須是前者)。

### 介面與資料形狀

組合定義檔為 schema 版本 1 JSON:專案清單,每項含識別碼(在檔內唯一)、顯示名稱、根目錄路徑(絕對或相對於定義檔)。

建置指令參數:組合定義檔路徑(必要)、輸出目錄(選用,預設為定義檔所在目錄下的 dashboard 子目錄)。輸出組合狀態物件 JSON,包含:schema 版本、組合定義檔路徑、每專案項目(識別碼、顯示名稱、根目錄、成功時內嵌該專案狀態物件與其板檔名、失敗時內嵌錯誤碼與原因、推導出的注意事項與其優先序類別)。

渲染指令參數:組合狀態物件路徑(必要)、輸出 HTML 路徑(選用,預設輸出目錄內固定檔名)。輸出不得包含存取碼、憑證、展開的執行參數、原始提示或環境值,不得參照任何外部資源。

### 失敗模式

組合定義檔缺失、無法解析、schema 版本不符、專案清單為空、識別碼重複時,建置指令以非零退出並輸出穩定錯誤碼,不產生任何輸出檔。個別專案的任何失敗不影響整體零退出,失敗詳情記載於該專案的錯誤卡片資料。渲染指令在組合狀態物件缺失或 schema 版本不符時以非零退出並輸出穩定錯誤碼。

### 驗收標準

- 執行 `portfolio-dashboard/scripts/check-portfolio-dashboard.mjs` 以零退出,輸出的檢查名稱涵蓋健康專案、未成立連線、已過期連線、執行逾期、根目錄不存在、組合定義檔無效、schema 版本不符七種情境。
- 在含兩個暫存專案(一健康、一缺根目錄)的暫存組合上,建置與渲染皆零退出,總覽 HTML 含一張正常卡片與一張錯誤卡片,正常卡片的連結指向輸出目錄內實際存在的專案板檔案。
- 產生的總覽 HTML 不含任何外部資源參照,可在無網路環境開啟。
- 執行 `scripts/install_agent_skills.mjs` 的 dry-run 將 portfolio-dashboard 列為可安裝 skill。
- git diff --check、spectra analyze add-portfolio-dashboard --json 與 spectra validate add-portfolio-dashboard 全部通過。

### 範圍邊界

**在範圍內**:`portfolio-dashboard` skill 的 SKILL.md、agents 鏡射、定義參考文件、範例組合定義檔、建置腳本、渲染腳本、檢查器,以及 README 的入口連結。

**在範圍外**:pipeline-board 的任何檔案與語意、agent-automation-orchestrate 的任何檔案與語意、即時更新、執行觸發、跨機器收集、歷史趨勢、其他 skill 的輸出模式。

## Risks / Trade-offs

- [受追蹤專案路徑隨時間失效] → 錯誤卡片明示根目錄不存在,不中斷其他專案;定義檔由使用者維護,儀表板不自行增刪。
- [pipeline-board 狀態物件 schema 演進造成誤讀] → 聚合檢查每份狀態物件的 schema 版本,不符時顯示版本不符錯誤卡片而非嘗試解讀。
- [設計師誤以為儀表板是即時狀態] → 頁面標示產生時間與重新產生方式,無任何動態進度元素。
- [總覽與各專案板時間點不一致造成矛盾] → 同一次聚合產生全部輸出,連結只指向同批產物。
- [專案數量多時建置時間線性成長] → 純檔案系統操作與子行程呼叫,無網路與 AI 呼叫,線性成本可接受;不做並行以維持輸出順序確定性。
- [子行程呼叫耦合 pipeline-board 的指令參數面] → 只依賴其文件化的輸入/輸出路徑參數與狀態物件 schema 版本欄位,檢查器以真實腳本驗證整合。

## Migration Plan

1. 建立 skill 外殼(SKILL.md、agents 鏡射)、定義參考文件與範例組合定義檔,確認安裝器能探索到。
2. 實作建置腳本:定義檔驗證與錯誤碼、逐專案子行程聚合、注意事項優先序推導,以暫存裝置驗證。
3. 實作渲染腳本與檢查器,補齊七種情境。
4. 在 README 加入入口連結。

回滾方式為移除 `portfolio-dashboard` 目錄。儀表板不寫入任何受追蹤專案、不修改既有設定、不建立服務,回滾不需資料遷移。
