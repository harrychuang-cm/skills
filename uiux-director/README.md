# UI/UX Director 說明文件

`uiux-director` 是給 PM 用的 UI/UX 設計總監。它先幫你弄清楚產品給誰用、為什麼用，再定出設計方向，並在你 Vibe Coding 的過程中把關體驗：使用者不會迷路、重點功能不會藏太深，功能也能隨時增刪。給 agent 讀的完整指令在 [SKILL.md](SKILL.md)，這份是給人看的導覽。

## 它幫你做什麼

- **釐清 TA 與產品目的**：一次問一題，每題都附建議答案，同意的話回「好」就可以。
- **問你想參考什麼**：自家的品牌色、logo、既有產品，和你喜歡的網站、App、截圖分開問。喜歡的參考一定會追問「喜歡它哪一點」，只借那一點，不照抄別人的 logo 和招牌色。截圖會存在 `product-design/references/`，任何時候貼上來都可以。
- **找參考案例**：從你給的參考開始，再研究競品、跨產業的類比產品與領域慣例，每一筆都附來源連結，不捏造。
- **定設計方向**：風格、呼吸感、配色、字級，用同一個畫面並排比較兩到三個方向，讓你直接看著選。
- **體驗健檢**：檢查使用者會不會迷路、核心功能要點幾下才到，寫成分 P0／P1／P2 的白話報告。
- **只動畫面的修正**：只修你勾選的項目，不碰資料流、state、API 與事件邏輯。
- **增刪功能**：加功能前先告訴你放哪、會不會把重要功能擠深；刪功能會一併清掉入口，不留死路。

所有決定都寫進專案的 `product-design/` 資料夾，下一次不管用 Claude Code、Cursor 還是 Codex，AI 都會照著做，不用重講一次。

## 五個模式

| 情境 | 模式 | 會得到什麼 | 可以這樣說 |
| --- | --- | --- | --- |
| 從一個點子開始，想定出方向 | `discover` | 四份文件與設計方向比較頁 | 用 uiux-director 幫我釐清這個產品：給退休族看存股的 App。 |
| 方向定了，要做畫面 | `build` | 你要的畫面，必要時附一兩句總監建議 | 照設計方向做自選股頁。 |
| 做到一半，想健檢 | `review` | 健檢報告，不改任何程式碼 | 幫我健檢 ./my-app，我怕使用者會迷路。 |
| 照報告修 | `fix` | 只改畫面的修正，以及修正摘要 | 修 P0-1、P0-2、P1-3。 |
| 加、刪、搬功能 | `feature-change` | 影響說明，確認後才改 | 我想加一個社群分頁。 |

Claude Code 與 Cursor 用 `/uiux-director`，Codex 用 `$uiux-director`。說「設計方向」「UX 健檢」「使用者會迷路」「功能藏太深」也會觸發。沒指定模式時，它會依你的需求和專案狀態判斷，並在第一句告訴你用了哪個模式。

## 範例對話

### 情境一：從 0 到 1

> **PM**：/uiux-director 我想做一個給退休族看存股的 App
>
> **總監**：這次用 `discover` 模式。先確認一件事：設計文件要用什麼語言寫？建議用繁體中文（直接回「好」即可），也可以選 English。
>
> **PM**：好
>
> **總監**：最常用這個產品的是誰？請描述一個具體的人。建議答案：60–70 歲、已退休、每週看一次持股、對專有名詞不太熟。
>
> **PM**：對，再加上多半用手機。
>
> ……（一次一題，問到 TA、目的、三個核心任務、成功指標為止）
>
> **總監**：整理如下（摘要）。確認的話我會寫進 `product-design/PRODUCT_BRIEF.md`，接著幫你找參考產品。
>
> ……
>
> **總監**：我做了三個方向的比較頁：`product-design/direction-comparison.html`，三個方向都用你的「持股總覽」畫面示範。A 字大、留白足；B 資訊量居中；C 偏緊湊。每個方向都附兩個參考產品和連結。要選哪一個，或混搭？
>
> **PM**：A 的密度，加 B 的配色。

### 情境二：Vibe Coding 做到一半

> **PM**：/uiux-director 幫我健檢 ./my-app，感覺使用者會迷路
>
> **總監**：這次用 `review` 模式，不會改任何程式碼。我從畫面推測主要使用者是盤中看盤的上班族、核心任務是看自選股、下單、設到價提醒，對嗎？
>
> **PM**：對。
>
> **總監**：報告在 `product-design/reviews/2026-11-26-review.md`。最嚴重的兩項：
> - P0-1：設到價提醒要從「⋯ → 設定 → 提醒 → 新增」進去，共 4 步，核心任務上限是 2 步。建議在個股頁直接放「設提醒」。
> - P0-2：空的自選股清單只寫「無資料」，沒有下一步。建議放「新增第一檔股票」。
>
> 要修哪幾項？修畫面之前，有沒有想參考的網站、App 或截圖？
>
> **PM**：修 P0-1、P0-2。字的大小想參考這張截圖（貼上），我喜歡它的數字很大。

## 會留下哪些文件

都在目標專案的 `product-design/` 資料夾：

| 檔案 | 內容 |
| --- | --- |
| `PRODUCT_BRIEF.md` | TA、產品目的、核心任務、成功指標、不做什麼、附來源的研究摘要 |
| `DESIGN_DIRECTION.md` | 八項設計決策、呼吸感（密度）設定、Material Design 3 token 計畫、刻意不做的事 |
| `EXPERIENCE_MAP.md` | 導航架構、步數上限、核心任務路徑、功能清單 |
| `DECISION_LOG.md` | 文件語言、每次決定的紀錄、還沒確認的問題 |
| `direction-comparison.html` | 設計方向比較頁 |
| `references/` | 你提供的參考截圖 |
| `reviews/日期-review.md` | 每次健檢的報告 |

- 第一次使用時會先問文件語言，預設繁體中文，記下來之後不再問。
- 沒有經過你確認的內容會標成 `unconfirmed`，並列在 `DECISION_LOG.md` 的待確認問題。
- 第一次建立文件後，它會在專案的 `AGENTS.md`／`CLAUDE.md` 加一小段標記區塊，讓之後的 AI 自動先讀這些文件。兩個檔案都不存在時，會先問你要建哪一個。

## 呼吸感怎麼定

呼吸感不等於「多留白」。留白太多本身就是 AI 味的一種。它是從 TA 推出來的：

| | 專業交易員 | 退休投資人 |
| --- | --- | --- |
| 為什麼 | 盤中要快速比價 | 要慢慢看、不想看錯 |
| 密度 | 緊湊 | 寬鬆 |
| 內文 | 14/20 | 18/28 |
| 一屏看到 | 15 檔以上 | 5–6 檔 |

每個數值都要寫出「為了這個 TA 的什麼需求」。只寫「看起來比較高級」的會被退回重想。

## 功能藏太深怎麼算

- **一步**＝從入口畫面起，點一下、開一次選單、選一個項目，算到能做那件事的畫面為止。
- **上限**：核心任務 2 步、次要功能 3 步，產品可以自己調整，但要寫原因。
- **直接不及格**：核心任務只能從「⋯／更多」、設定頁，或滑鼠移上去才出現的按鈕進入。

報告會列出實際計算的路徑，例如「首頁 → 點自選股 → 點個股（看得到買進鈕）」，你可以自己複算。

## 設計 token：用 Material Design 3 的方法

設計 token 是把顏色、字級、間距、圓角取好名字，讓整個產品共用。這個 skill 採用 Google Material Design 3（MD3）的方法：

- **三層**：ref 放原始數值（某個藍色的第 40 階），sys 放用途（「主要按鈕的顏色」），comp 放元件的設定（「下單按鈕的底色」）。畫面只用 sys 和 comp，不直接寫色碼。
- **方法，不是外觀**：不會因此長得像 Google 的 App。不會沿用 MD3 預設的紫色和 Roboto，主色要從你的品牌或 TA 推出來。
- **領域語意另外命名**：例如台股紅漲綠跌，會用「漲」「跌」專用的顏色角色，不拿「錯誤紅」來代替。
- **既有專案**：已經有自己的 token 就做對應表，不另外重建一套；完全沒有的話，會先列出最小的一組請你同意，才會建立。

詳細規則在 [references/md3-token-method.md](references/md3-token-method.md)。

## 和其他 skill 的關係

- `anti-ai-style`：負責判斷畫面像不像 AI 做的。做畫面前預防、健檢時審查。沒安裝時用本 skill 的精簡底線，並會說明。
- `ds-governance`：負責 token 與共用元件的決定與核准。
- `storybook-product-prototype`：要做 Storybook 原型與交接文件時，把 `product-design/` 的文件交給它。
- `figma-m3-variables`：設計稿在 Figma 時，用它把 token 計畫建成 Figma Variables（有安裝才會用）。

## 目前的限制

- **步數檢查腳本延後到第二階段**：目前步數由 AI 依 [references/experience-review.md](references/experience-review.md) 的規則手動計算，報告會列出路徑讓你複查。
- 研究需要 agent 有網路搜尋工具。沒有時會明說，並請你提供參考產品的連結。
- 比較頁是方向示意，不是最終畫面；正式畫面還是走 `build` 與設計系統。

## 安裝

在 cm-skills repo 根目錄執行：

```sh
node scripts/install_agent_skills.mjs --agent all --scope user --skill uiux-director --dry-run
node scripts/install_agent_skills.mjs --agent all --scope user --skill uiux-director
```

建議一併安裝 `anti-ai-style` 與 `ds-governance`。
